# CRUD 联调契约检查表

在补 mock 之前，先按下面清单过一遍。

## 1. 接口定义

- 资源名是什么
- 列表、详情、创建、更新、删除分别对应什么路径
- 更新到底用 `PUT` 还是 `PATCH`
- 是否带导入、导出、分页、搜索、状态切换

## 2. 前端消费方式

- query hook 是怎么调用接口的
- mutation 成功后会刷新哪些 query key
- 页面最终使用的是接口原始字段，还是 query 层映射后的字段
- 错误时是抛异常、返回空数组，还是走本地 fallback

## 3. 请求结构

- path params
- query params
- body
- formData 字段名
- 是否需要 `responseType: "blob"`

## 4. 响应结构

- 是否统一走 `response.data.data`
- 列表是否要保留后端风格字段名
- 详情是否必须返回完整对象
- 删除返回 `null` 还是 `{ success: true }`
- 时间字段是秒级还是毫秒级

## 5. 本地状态设计

- 是否需要 `seed` 初始化
- 是否需要 `Map` 作为内存 store
- 是否需要 `version` 做并发控制
- 更新时是覆盖还是 merge
- 删除后是否要同步影响列表和详情

## 6. 异常分支

- 404 不存在
- 400 参数缺失
- 500 未知异常

## 7. 联调验收

- 列表打开正常
- 详情打开正常
- 创建成功后能立刻看到
- 更新成功后 UI 状态一致
- 删除成功后 UI 状态一致
- 导入导出可触发
- 页面报错分支可控
